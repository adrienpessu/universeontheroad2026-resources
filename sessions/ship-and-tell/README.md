
# Ship & Tell

## Universe on the Road 2026 — City Execution Guide

Ship & Tell celebrates what attendees build using the GitHub Copilot app during the hands-on experience. At the end of the day, selected projects are showcased on the main stage, the audience selects three finalists, and a second vote determines first, second and third place.

The goal is an interactive, community-led finish to the event. Keep submissions straightforward, prepare project media before the session and give attendees a chance to celebrate each other's work.

| Detail | Recommended format |
| --- | --- |
| Showcase | Five projects, with one reserve if possible |
| Pitch | Up to 90 seconds per project |
| Voting | Two rounds: five projects to three finalists, then first to third place |
| Session | 25 minutes; confirm the local event schedule |
| Submission cutoff | At least 30 minutes before the session (for example, 15:00 for a 15:35 start) |

## 1. Assign responsibilities before the event

| Role | Responsibility |
| --- | --- |
| Terminal / hands-on station team | Encourage participation and collect project screenshots or recordings |
| Submissions lead | Review submissions, choose finalists and a reserve, confirm availability |
| Stage / AV team | Transfer project media, update the host deck and test playback |
| Stage host | Introduce finalists, manage pitch timing, lead voting and announce winners |
| Event / marketing support | Organise prizes, finalist coordination and photography if required |

Roles can be combined for smaller events, but every handoff should have a clear owner.

Confirm the venue's rules for removable drives, shared folders, recording and displaying attendee content. Agree on the voting method and tie-break process in advance.

## 2. Encourage project submissions

The Terminal team should invite attendees to build something useful, interesting or creative with the GitHub Copilot app. Examples include a small game, application or solution to a technical problem.

When a participant is ready:

1. Record their name, project title and a way to contact them during the event.
2. Capture a screenshot (PNG/JPG) or short screen recording (MP4).
3. Save the file using a consistent name such as `First-Last_Project.mp4`.
4. Confirm they are willing to have their project shown on stage and can stay for the finale.
5. Check media for secrets, private information or other content that should not be projected.

Station staff should actively nominate promising projects instead of relying entirely on self-submission.

## 3. Select the finalists

Close submissions at least 30 minutes before the showcase. The submissions lead should:

1. Gather all entries in one approved location.
2. Select five varied projects based on creativity, usefulness, clarity and effective use of Copilot.
3. Keep one reserve project if possible in case a finalist is unavailable.
4. Confirm every finalist is still at the event and willing to present.
5. Give each finalist the 90-second pitch brief: what they built, how Copilot helped and why it is interesting.
6. Provide the ordered list, project names and media to the host and AV team.

## 4. Prepare the stage

Add the five selected screenshots or recordings to the host presentation deck in the confirmed order. Display each participant's name and project title.

- Transfer files to the stage laptop using an approved shared folder or authorised USB drive.
- Embed recordings locally rather than depending on attendee laptops or live websites.
- Test every clip and slide in presentation mode, including audio and transitions.
- Keep a still screenshot available if playback fails.
- Confirm who advances slides, operates media and keeps time.

## 5. Run the finale

| Stage activity | Suggested duration |
| --- | ---: |
| Introduce Ship & Tell and explain voting | 1.5 min |
| Five pitches and transitions | 10 min |
| Round 1: select the three finalists | 2.5 min |
| Round 2: determine the podium | 2.5 min |
| Announce winners, prizes and photograph | 3.5 min |
| Close and transition to reception | 2 min |
| Contingency buffer | 3 min |
| Total | 25 min |

In Round 1, the audience votes on the five showcased projects to select three finalists. In Round 2, use a fresh vote among those three projects to determine first, second and third place. Do not carry scores from the first round into the second.

Choose one method for both rounds:

- Digital polling: Use an approved platform, test both polls and the QR code, and prepare a fallback.
- Audience applause: Ask for applause for each project in the same order, have two team members help assess the response and run a head-to-head tie-break where needed.

Announce winners in third-, second-, then first-place order. Thank all participants and hand back to the host or transition into the reception.

## 6. Handle common issues

| Situation | Action |
| --- | --- |
| Finalist has left | Use the reserve project or an agreed presenter with the creator's permission |
| Video fails | Display the backup screenshot |
| Digital polling fails | Switch to pre-briefed applause voting |
| Applause result is tied | Run a short head-to-head vote |
| Running out of time | Reduce pitches to 60 seconds and shorten media playback |
| Fewer than five submissions | Showcase the available projects and explain the adjusted format |

## Final checklist

- [ ] Local session timing and submission cutoff confirmed.
- [ ] Named owners assigned for stations, submissions, AV, host, voting and prizes.
- [ ] Collection location and file naming agreed.
- [ ] Five finalists and one reserve selected where possible.
- [ ] Finalists available, briefed and comfortable with displaying their work.
- [ ] Media transferred to the host deck and tested on the stage laptop.
- [ ] Voting method, second round and tie-break rehearsed.
- [ ] Prizes, photography and closing transition confirmed.

Ship & Tell works best when the team handles the logistics quietly and the audience gets to enjoy what attendees have made.
